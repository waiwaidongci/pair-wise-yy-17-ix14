# 钟乳石洞穴巡测 · 季末封存与开季复开

围绕洞穴样点记录微环境巡测，并在每季之间完成「季末封存 → 开季复测 → 路线复开」闭环。

## 启动

```bash
npm install
npm start          # http://localhost:3912
npm test           # 规则层单元测试（27 项）
```

数据保存在 `data/db.json`（临时文件原子落库）。

## 分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 规则 | `rules.js` | 封存/复测/复开的全部判定与结论失效联动，纯函数，不碰 HTTP 与文件 |
| 存储 | `store.js` | JSON 读写、写队列串行化（读-判-写同一临界区）、临时文件原子替换 |
| 接口 | `server.js` | Express 薄路由层，调用规则，统一错误码（规则不满足 → 409） |
| 页面 | `public/` + `project.config.js` | 配置化视图、领域表单、预检与履历展示 |

## 业务规则

### 季末封存（按样点）
- **每样点每季仅一张封存单**；同季已存在有效封存单时拒绝并返回首单编号。写操作经存储层串行队列处理，并发请求只认首单。
- 封存须**补齐本季巡测**：封存季的每个自然月至少一条读数齐全（温度/湿度/CO2/滴水频率）的有效巡测；已撤回巡测不计。
- 样点**暂停开放**不得封存；巡测**缺项**不得封存。
- 封存单失效后可重新封存（另开新单，履历保留）。

### 开季复测（按样点）
- 开季前，路线内每个样点须由**两人、间隔至少 24 小时各测一次**。同一人不能测两次，间隔不足拒绝登记。
- 两条复测满足人员/间隔要求后自动判定：
  - 温差 **> 0.8℃**、湿度差 **> 5 个百分点**、CO2 **增量 > 100ppm**（任一成立）→ 样点只转**待校准**，记录超阈原因；
  - 阈值采用「超过」语义（恰好等于阈值合规），CO2 只看增量不看降幅。
- 暂停开放样点不得登记复测。撤回不合规复测后，按剩余记录重算待校准状态。

### 路线复开（按路线）
- 按路线整体评审：路线内**每个**样点都须满足「上一季已封存 + 双人隔时复测合规 + 未暂停开放 + 非待校准」。
- 任一样点不满足，**整条路线不得复开**，开具「不予复开」单并逐点列出阻断原因（页面可先「预检」）。
- 全部满足开具「已复开」单；同一路线每季仅一张有效复开单。

### 原结论失效
- **修订基准**（基准温度/湿度/CO2）：该样点全部有效封存单失效；涉及该样点的路线复开单失效。
- **撤回巡测**：该样点当季封存单失效（本季巡测不再齐全）。
- **撤回开季复测**：对应路线复开单失效，待校准状态按剩余复测重算。
- 样点改挂路线：新旧路线复开单均失效。
- 失效不删除单据，状态置为「结论失效」并写入履历；单据状态不接受前端直接改写。

## 数据集合

- `sites` 样点档案（含基准、保护状态、待校准状态）
- `surveys` 巡测记录
- `sealOrders` 封存单（已封存 / 结论失效）
- `reopenChecks` 开季复测（有效 / 已撤回）
- `reopenOrders` 复开单（已复开 / 不予复开 / 结论失效）

## 主要端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/seals` | 开具封存单 |
| POST | `/api/reopen-checks` | 登记开季复测 |
| POST | `/api/reopen-checks/:id/withdraw` | 撤回复测 |
| GET | `/api/routes/:route/reopen-evaluation?season=` | 路线复开预检 |
| POST | `/api/reopen-orders` | 路线复开评审 |
| POST | `/api/surveys/:id/withdraw` | 撤回巡测 |
| PATCH | `/api/sites/:id` | 样点更新（基准修订触发联动） |
